# nib 0.14.0

Opt-in plugin packages, DeepSeek defaults, and quieter edit results.

## Plugin packages

- Install a local directory or Git package with `nib plugin install <source> [--path <subdir>]`. Packages can supply namespaced skills, manual Markdown commands and supported MCP definitions, using a documented subset of the Claude-style package format.
- Every installation or reinstall starts disabled. Use `nib plugin on <name>` or `/plugins on <name>` to enable it for new Sessions; `list`, `off` and `uninstall` are also available. Unsupported components are reported, not executed. There is no marketplace, install-script execution or general plugin runtime API.
- Existing Sessions, children and forks keep their package catalog and MCP snapshot. Uninstall unregisters a package but retains stored files needed by old Sessions. Selecting a model before the first message preserves the active catalog. MCP environment templates resolve at launch, including in child agents, without saving credential values in snapshot metadata.

## Models

- New DeepSeek Sessions default to `delivery=tool`: background results and interjections arrive with tool results, and `tools.wait()` lets the model wait without inserting a new user message mid-Turn.
- DeepSeek also defaults to `validation=none`, removing nib's explicit build/test and full-validation nudges. Models may still run checks, and user/project instructions still apply. Other model families keep their existing guidance.
- `NIB_TUNE=validation=single` selects the original guidance; `existing-only` and `none` are the other validation variants. `delivery=user` and `delivery=tool` select result delivery for comparisons. The chosen variants are recorded and retained when resuming. Old Sessions keep their original prompt and behavior.
- Custom endpoints can set an optional `max_output`; it is sent to Chat Completions and Messages endpoints where supported.

## Runs and interface

- Expanding a successful Run containing only edit/write calls shows Changes only when complete tool metadata confirms no failed calls. Mixed-tool Runs, warnings, caught tool errors and older or incomplete metadata retain Result and Script, in both normal and Simple modes.
- Runtime JS errors now include the same bounded source context as syntax errors, while preserving their error and stack.
- Chat Completions responses that explicitly signal a tool call without supplying one report a protocol error instead of normal completion. Assistant text is never promoted to executable code.
- The activity line keeps a blank row between status and the transcript.

# nib 0.14.0（中文）

默认关闭的插件包、DeepSeek 默认调优，以及更简洁的编辑结果。

## 插件包

- 使用 `nib plugin install <source> [--path <subdir>]` 安装本地目录或 Git 插件包。插件包可以提供带命名空间的技能、手动调用的 Markdown 命令，以及支持的 MCP 定义；兼容范围是文档明确列出的 Claude 风格包格式子集。
- 每次安装或重新安装都默认关闭。使用 `nib plugin on <name>` 或 `/plugins on <name>` 为新 Session 启用，也支持 `list`、`off` 和 `uninstall`。不支持的内容会被报告，不会执行；没有插件市场、安装脚本执行或通用插件运行时接口。
- 已有 Session、子 agent 和 fork 保留原来的插件目录及 MCP 快照。卸载会取消注册，但保留旧 Session 所需的包文件。首次消息前切换模型不会丢失已启用的目录。MCP 环境变量模板在启动时解析，子 agent 同样适用；凭证值不会写入快照元数据。

## 模型

- 新建 DeepSeek Session 默认使用 `delivery=tool`：后台结果和中途插话附在工具结果中送回，模型可以用 `tools.wait()` 等待，避免在一轮中途插入新的 user 消息。
- DeepSeek 同时默认使用 `validation=none`，去掉 nib 主动引导构建、测试和完整验证的文字。模型仍可自行检查，用户及项目指令照常生效；其他模型家族保留原来的验证引导。
- 可用 `NIB_TUNE=validation=single` 选择原来的验证引导，其他验证选项为 `existing-only` 和 `none`；`delivery=user`、`delivery=tool` 用于对比结果投递方式。实际选择会记入日志，恢复会话时沿用；旧 Session 保留原提示词及行为。
- 自定义端点可选配 `max_output`，在支持的 Chat Completions 和 Messages 端点中发送。

## Run 与界面

- 成功且只包含 edit/write 调用的 Run，在完整工具元数据确认没有失败调用时，展开后只显示 Changes。混合工具、警告、被捕获的工具错误，以及旧的或不完整元数据仍保留 Result 和 Script；普通模式和 Simple 模式均适用。
- JS 运行时错误会像语法错误一样附带有长度上限的源码片段，同时保留原错误和堆栈。
- Chat Completions 响应明确表示调用工具，却没有提供工具调用时，会报告协议错误，不再正常结束。不会把助手正文当作代码执行。
- 活动状态行与会话记录之间保留一行空白。
