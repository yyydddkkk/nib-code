# nib 0.17.0

Resume sessions after switching models on the same provider, with more reliable background Run delivery and a more responsive TUI.

## Sessions and providers

- Resume a session with a different model on the same provider without losing messages, tool calls, or results. Encrypted or signed continuation data is replayed only with the model that produced it. Cross-provider resume and incompatible forks are still rejected.
- Startup, `/provider`, `/model`, `/status`, and child sessions now use the same credential rules. Sign-out removes only nib-managed credentials; environment keys and external Codex CLI credentials remain available. Custom endpoints can still run without a key.
- Background results are committed with the session history that receives them, including results folded into a tool response or consumed by `tools.wait`. Replay and rerun use recorded Run data rather than display text, and resume restores pending output-byte accounting without double-counting. Older logs remain readable without migration.

## TUI and development

- Run detail rendering and mouse hit-testing use the same layout, so wrapped headings remain clickable when the viewport clips them.
- Large bracketed pastes are buffered instead of redrawing for every key. The TUI refreshes when the paste ends.
- `scripts/dev-install.sh` builds from a pinned local `main` commit and installs `nib-dev` without replacing stable `nib`. Normal PRs still run full Linux and macOS CI; version-and-release-note-only PRs use a lightweight check.

# nib 0.17.0（中文）

现在可以在同一服务内切换模型后恢复会话；后台 Run 结果投递更可靠，TUI 响应也更流畅。

## 会话与服务

- 在同一服务内切换模型后，可以恢复原会话并保留消息、工具调用和结果。加密或签名的续接数据只会在使用原模型时回放。跨服务恢复和不兼容的会话分叉仍会被拒绝。
- 启动、`/provider`、`/model`、`/status` 和子会话使用统一的凭据规则。登出只移除 nib 管理的凭据，不影响环境变量中的密钥或外部 Codex CLI 凭据。自定义端点仍可在不需要密钥时使用。
- 后台结果与接收它们的会话历史一起提交，包括折叠到工具响应的结果和由 `tools.wait` 消费的结果。回放和重跑使用记录中的 Run 数据，而不再解析展示文本；恢复会话时会还原待计入的输出字节，避免重复计数。旧日志无需迁移，仍可读取。

## TUI 与开发

- Run 详情的绘制与鼠标命中检测共用同一套布局，换行后的标题即使被视口裁切也能点击。
- 大段括号粘贴会先缓冲，避免逐键重绘，并在粘贴结束时刷新界面。
- `scripts/dev-install.sh` 从本地 `main` 的固定提交构建并安装 `nib-dev`，不替换稳定版 `nib`。普通 PR 仍运行完整的 Linux 和 macOS CI；只修改版本号和发布说明的 PR 走轻量检查。
