# Keep system stable; compact context at complete Step boundaries

**Decision:** New Sessions write cwd and original system in the first record of `$NIB_HOME/sessions/<32hex>.jsonl` (default `~/.nib/sessions/`). system concatenates base instructions, global AGENTS.md, then project AGENTS.md. Resume retains logged text; instruction changes affect new Sessions only. Subsequent history updates go through commit, appending logs, updating memory, and syncing. Commit a Step's assistant and all tool results together, including the user message for the first Step. Exclusive Session locks prevent concurrent resume; crashes' damaged tails are isolated by appending a newline and repair record without truncating the original file.

Check context before each Step, after delivering queued inputs, and automatically compact at roughly 75% of the window. TUI `/compact [focus]` also requests manual compaction. Before requesting a summary, budget for the unchanged system, committed but unsent messages, pending inputs and the summary itself. The replacement must reduce the local token estimate, fit within half the window, and leave the next request below the automatic trigger once pending input is added.

Prefer keeping the latest two Turns verbatim. The ordinary tail budget is a quarter of the live conversation estimate (at least 8192 tokens where available, capped at a quarter of the window). If the preferred Turns do not fit, keep a shorter suffix at complete Step boundaries. The newest Step can use the available room beyond the ordinary tail budget; if it still does not fit, summarize it too instead of splitting its tool group or failing compaction. Do not prune or re-truncate retained Run results. The model receives the existing prefix for summarization, with older images represented by text placeholders. Request a summary budget of one eighth of the smaller of the conversation estimate and the window (32–2048 tokens), reduced as needed to fit. Replace the archived prefix with one user summary followed by retained messages and append a `from=1` replacement record. Original messages remain in the log. Compaction notices compare the same estimate on both sides; actual usage for the next request remains in the Step log.

**Why:** Fixed system stabilizes request prefixes and isolates resume from instruction changes. Summary requests reuse old message prefixes and append summarization instructions to use caches, rather than re-encoding history as one large text block. The replacement prefix invalidates subsequent caches, so targeting half the window creates headroom before returning to append-only updates. A user summary avoids elevating model-generated content to system instructions. Complete Step boundaries preserve tool call/result pairing; recent verbatim context preserves work details. Append-only replacement records express new context without rewriting logs or introducing another store. Model context is resumable; external command/file effects are not rolled back.

**Sources and confidence (2026-11-01):** Primary source: `src/session.zig`, `src/session/log.zig`, `src/session/instructions.zig`, `src/tools.zig`, `src/main.zig`, `src/tui.zig`. Measured: unit tests verify replay matches in-memory safe points; mocks verify resume, automatic compaction in a 4096-token window, and TUI `/compact`. 75%, half, two Turns, and 2048 tokens are initial heuristics without real-model long-Session measurements. Summaries may lose detail; reported usage and byte estimates do not precisely predict the next request's tokens.

**Continue on failure:** Automatic compaction is best effort. If the budget is exhausted before requesting a summary, the summary is ineffective, or its request fails (except cancellation/out-of-memory), issue a notice and continue with unchanged history. Wait for another 1/8-window growth before retrying an ineffective attempt. Fewer than three complete Steps does not back off, as another Step can provide a cut point.

**Codex summaries (2026-11-01):** Always use the current Session's model to reuse cached prefixes and avoid passing encrypted reasoning between models. Use none when reasoning can be disabled; pi marks gpt-6.1-sol/gpt-6-astra as unable to disable, so use minimum low. Codex does not reuse the small total-output limit: like pi, omit max_output_tokens and preserve normal server budgets. The planned 32–2048-token budget constrains only summary text, leaving room for reasoning plus summary (pi catalog maxTokens 128000; backend determines actual quota). Empty summaries, incomplete/truncated responses, or ineffective compaction follow the notice-and-continue policy above; manual compaction errors. See [0011](0011-provider-wire-protocols.md) for protocol differences.

**When to reconsider:** Real long Sessions still exceed windows or compact repeatedly; omitted details cause errors; summarizing an oversized recent Step causes loss of important details; model windows/output budgets change; or actual needs arise for restoring unfinished Steps, auditing every Tool side effect, or forking Sessions.
