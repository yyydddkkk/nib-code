# Keep system stable; compact context at complete Step boundaries

**Decision:** New Sessions write cwd and original system in the first record of `$NIB_HOME/sessions/<32hex>.jsonl` (default `~/.nib/sessions/`). system concatenates base instructions, global AGENTS.md, then project AGENTS.md. Resume retains logged text; instruction changes affect new Sessions only. Subsequent history updates go through commit, appending logs, updating memory, and syncing. Commit a Step's assistant and all tool results together, including the user message for the first Step. Exclusive Session locks prevent concurrent resume; crashes' damaged tails are isolated by appending a newline and repair record without truncating the original file.

Check context before each Step and automatically compact at roughly 75% of the window. TUI `/compact [focus]` requests the same operation manually. Keep the original system prompt. Plan for a next input around **10% of the window**, reserving room for the system prompt, tool definitions, pending input, latest user request, and summary. Choose a recent suffix by estimated tokens (at most 16,384), picking only whole assistant/tool groups. If fixed input already consumes the target, keep a small working tail when it fits. The target is not a rejection threshold: an oversized system prompt or user request cannot be fixed by summarizing other history.

Summarize older history with the current Session model. Update the previous handoff rather than stacking summaries. The new handoff should preserve current constraints, decisions, file and test state, actionable errors, live task IDs and unfinished work. The text budget is one eighth of the smaller of the conversation and window, clamped to 32–2048 tokens and further limited by available space. Replace older messages with one user-role handoff, the original latest user request if not otherwise in the next input, and the kept suffix. An oversized retained tool result can be replaced by a short head/tail preview and a reference to its exact recorded text in the existing Session output store. If even the newest Step is summarized, the handoff can include up to three recent large-result references. The model can page those files with `tools.read`, including after resume or fork. The references carry the text originally recorded, not data already discarded by Run formatting, and do not restore image attachments.

Preserve any trailing input not yet consumed by a complete Step. Append a `from=1` replacement record only when history shrinks, the compacted history fits within half the window, and the next estimated input stays below the automatic trigger. Write referenced files before the replacement record. This changes next-request context without deleting old records or re-executing tools.

Run results retain roughly 16 KiB total head/tail plus a truncation notice. This is roughly 4K English tokens, a byte-scale estimate rather than tokenizer measurement.

**Why:** Fixed system stabilizes request prefixes and isolates resume from instruction changes. Summary requests reuse old message prefixes and append summarization instructions to use caches, rather than re-encoding history as one large text block. The replacement prefix invalidates subsequent caches, so targeting a short next input creates headroom before returning to append-only updates. A user summary avoids elevating model-generated content to system instructions. Complete Step boundaries preserve tool call/result pairing; recent verbatim context preserves work details. Append-only replacement records express new context without rewriting logs or introducing another store. Model context is resumable; external command/file effects are not rolled back.

**Failure and retry:** Automatic compaction is best effort. If the summary request fails (except cancellation/out-of-memory), writing an output reference fails, or the result does not reduce the estimate, leave history unchanged and continue the Turn normally. Back off by another one eighth of the context window after a failed or ineffective attempt. With fewer than three complete Steps, skip without backing off. Manual compaction surfaces errors.

**Validation:** Local mocks exercise context reduction, follow-up requests, repeated summaries, recovery of a compacted tool result after resume, and inherited context in forks. Token budgets are estimates, not a guarantee of provider-reported input usage or of summary quality.

**Codex summaries (2026-11-01):** Always use the current Session's model to reuse cached prefixes and avoid passing encrypted reasoning between models. Use none when reasoning can be disabled; pi marks gpt-6.1-sol/gpt-6-astra as unable to disable, so use minimum low. Codex does not reuse the small total-output limit: like pi, omit max_output_tokens and preserve normal server budgets. The original 32–2048-token budget constrains only summary text, leaving room for reasoning plus summary (pi catalog maxTokens 128000; backend determines actual quota). Empty summaries, incomplete/truncated responses, or ineffective compaction follow the notice-and-continue policy above; manual compaction errors. See [0011](0011-provider-wire-protocols.md) for protocol differences.

**When to reconsider:** Real long Sessions still exceed windows or compact repeatedly; omitted details cause errors; too little recent context survives; model windows/output budgets change; or actual needs arise for restoring unfinished Steps, auditing every Tool side effect, or forking Sessions.
